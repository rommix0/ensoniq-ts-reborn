# VFD Font Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The panel's display draws its characters and cursor in the Ensoniq VFD font's Regular weight.

**Architecture:** The OTF is compiled into the app's binary data; `PanelEditor.cpp` makes one typeface from it and a
helper sizes it to a display cell; `DisplayPart::paint` draws each cell's glyph at its baseline and the cursor bar
under it. The hex overlay keeps the monospaced font.

**Tech Stack:** C++17, JUCE 8 (app only), `app/tests/app_tests.cpp`.

**Spec:** `docs/design/2026-11-27-vfd-font-design.md`.

## Global Constraints

- AGENTS.md: JUCE only in `app/`; app checks headless, never the user's settings; warnings clean at `/W4` and
  `-Wall -Wextra`; lines up to about 120 columns.
- The font file is copied unchanged: `misc/ensoniq-vfd-font-main/fonts/EnsoniqVFD.otf` and
  `misc/ensoniq-vfd-font-main/OFL.txt` to `app/resources/fonts/`.
- Glyph advance 720/1000 em = one cell (`kDisplayText.w / 40`); ink 0.058-0.818 em above the baseline, centred in
  the row; cursor bar x 0.053-0.509 em, 0.086-0.164 em below the baseline, rounded ends.
- Codes 0x00-0x1F and 0x7F stay blank; the hex overlay and A113's blink are unchanged.
- Decision A141 in `docs/decisions.md`; `// DECISION A141` at the font helper and in `DisplayPart::paint`.

## Review Focus

1. A typeface that fails to load (corrupt binary data): the display still draws, in the monospaced font, never
   crashes (code read; the helper falls back).
2. A glyph wider than its cell at some window size: never dropped (drawn at its baseline, not by `drawText`).
3. The cursor at the bottom row: the bar stays inside the display window (Task 1 check, the underlined cell).
4. The no-ROMs message's lowercase letters: drawn from the font (it covers 0x20-0x7E), not blank (Task 1 Step 4, the
   `panel-noroms.png` snapshot looked at).
5. Linux: the font loads from memory the same way (Task 2, app checks on Linux).

- [ ] **Step 1: Write the failing check** `vfd_font` (beside `editor` in `main`):

```cpp
// DECISION A141: the display's font is Ensoniq VFD Regular, one glyph advance per cell.
void vfdFontCheck() {
    for (const float cell : {8.48f, 14.125f, 28.25f}) {
        const auto f = vfdFont(cell);
        CHECK(f.getTypefaceName() == "Ensoniq VFD");
        for (const char* s : {"A", "W", "0", "_"})
            CHECK(std::abs(juce::GlyphArrangement::getStringWidth(f, s) - cell) < cell * 0.01f);
    }
}
```

and, in the same check, the cursor bar for a cell of 14.125 with its baseline at (100, 50):
`vfdCursorBar(14.125f, {100, 50})` is x 100 + 0.053 em to 100 + 0.509 em, y 50 + 0.086 em to 50 + 0.164 em
(em = 14.125 / 0.72), each within 0.01. With the ink centred, the bar's bottom is 0.602 em below the row's centre,
inside the row's half-height of 1.03 em (Review Focus 3). The `editor` check's lit display pixels stay as they are.
