# TS Floppy Drive Implementation Plan (Plan 5)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The emulated TS-10's floppy drive works: the unmodified OS loads EPS, EPS-16 PLUS and ASR-10 sampled sounds from disk image files, and what it writes can be saved back to image files, in the Standalone and the VST3.

**Architecture:**
- **A disk** (`src/ts/disk.*`) is 80 cylinders x 2 heads of 512-byte sectors, 10 per track (double density) or 20 (high density), each track formatted or not. **Codecs** (`src/ts/disk_image.*`) turn raw, GKH and Giebler (EDE/EDA/EDT) files into a disk and back, on byte buffers.
- **The uPD72069** (`src/ts/fdc.*`) grows from today's empty-drive answers to the uPD765 command set the OS uses, moving data in non-DMA mode one byte per access, never making the OS wait.
- **The machine** holds the drive and drives the DUART lines (index IP0, disk change IP1, density IP2). **The engine** swaps disks in and copies them out across threads without locking. **The app** gives the panel's drive a menu: open, new blank, save, save as, eject, write protect.

**Tech Stack:** C++17, CMake 3.20+, `tests/check.h`; JUCE 8.0.16-security (from the KS-32 checkout, as Plan 4) for `app/`.

**Spec:** `docs/design/2026-11-14-ts-floppy-design.md` ("design"). Background: `docs/ts-hardware-interface.md` ("Floppy controller and the empty drive", T10), `docs/tsapp.md`, the Mirage project's disk handling (`C:\Users\abart\Desktop\Ensoniq Mirage\emulator`: `engine/src/disk_image.cpp`, `engine/src/edm_format.cpp`, `docs/app.md`; a WD1772 machine, so patterns only, no code).

## Global Constraints

- **AGENTS.md rules.** The firmware runs unmodified; studying it (the OS disassembly) is allowed and is cited in decision entries. MAME is not a reference. No JUCE, OS calls or file I/O under `src/`; `src/ts` stays integer-only. Tests never touch the user's settings, memory or disk files.
- **Determinism.** With no disk, these stay identical on MSVC x64, MinGW i686 and Linux GCC: boot trace `3bfc7336098a6def`; renders `4a751109deae8b89` (`player_smoke.mid`), `524fcc64af78f175` (`full_chord.mid`), `01e3c8622cc8c8be` (`filtered_patch.mid`).
- **Builds.** Everything except `app/` builds without warnings on MSVC x64 (`build-msvc/`, `/W4`), MinGW (`build/`, `-Wall -Wextra`, `C:\winlibs\mingw32\bin` on PATH) and Linux GCC (`build-linux/`, WSL). `app/` builds on MSVC x64 (`build-app/`) and Linux GCC (`build-linux-app/`) with no warnings from our files.
- **Real time.** Once booted, nothing `Engine::render` or `processBlock` calls may allocate, lock (other than `try_lock`) or wait. `ens_rt_tests` enforces it.
- **Speed.** `build-msvc\Release\tsemu.exe bench` stays at realtime x2 or more.
- **Disk images.** Tests that need the user's images read them from `ENS_DISK_DIR` (a CMake cache path like `ENS_ROM_DIR`, default empty); without it a test prints `  skip: disk images not found` and passes. Nothing is ever written under `ENS_DISK_DIR`; tests write only to a temporary folder. No disk image is committed.
- **Headless.** Never start `TS Reborn.exe` or a plugin GUI; the app checks run headless.
- **Decisions.** Each call gets `// DECISION <id>: <one line>` at the point of use and an entry in `docs/decisions.md` in the existing format: machine calls `T21` onward, app calls `A118` onward.
- **Branch.** `plan5-floppy` in a worktree, a commit per task, merged into `main` with a merge commit. Nothing is pushed.

## Review Focus

- A file that is not a disk image (wrong size, a `.hfe`, a text file) is refused with a message naming the sizes or formats expected, and the drive keeps what it had (Task 1, Task 6).
- Ejecting or swapping the disk while the OS is reading it gives the OS's own disk error, never a crash or a hang (Task 3, Task 5).
- A save requested just as the disk is swapped copies the right disk or reports that it could not; it never writes one disk's sectors under another's name (Task 5).
- A block the OS writes into a Giebler file's omitted (all-zero) block is kept by Save (Task 1).
- A disk of the other density in the drive gives the OS's error message, not a wedge (Task 3).

  - `fdc_empty_drive_unchanged`: no disk: Sense Drive Status `04 00` answers ST3 `0x00`; Read Data answers ST0 `0x48`. (The empty-drive answers T10 pins, so the hashes hold.)
  - `fdc_recalibrate_and_seek`: with a DD disk, `07 00` then Sense Interrupt Status `08` answers ST0 `0x20` (seek end) and PCN 0; `0F 00 05` then `08` answers `0x20` and 5; `cylinder() == 5`.

  - `fdc_write_data_counts_write`: Write Data `45 ...` with 512 bytes changes the sector and `writes()` goes up by 1; with write protect on, ST0 `0x40` and ST1 has NW (0x02), the sector unchanged.
  - `fdc_missing_sector`: R = 12 on DD: ST0 `0x40`, ST1 ND (0x04).
  - `fdc_unformatted_track`: Read Data on a blank disk: ST0 `0x40`, ST1 MA (0x01).
  - `fdc_format_track`: Format Track `4D 00 02 0A ...` with 10 ID fields (C H R N) written as the data phase formats the track with the filler byte and makes its sectors readable.
  - `fdc_read_id`: `4A 00` on a formatted track answers ST0 `0x00` and C H R N of a sector on the track.
  - `fdc_wrong_rate`: an HD disk with `setHighRate(false)`: Read Data and Read ID answer ST0 `0x40`, ST1 MA (0x01).
