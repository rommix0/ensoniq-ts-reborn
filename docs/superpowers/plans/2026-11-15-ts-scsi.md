# TS Reborn SCSI and CD-ROM Implementation Plan (Plan 7)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The SP-4 SCSI option with one CD-ROM drive at ID 4 reading the user's Ensoniq CD images on demand, and VST3 projects that bring back sampled sounds loaded from floppy or CD by saving only the blocks the OS read.

**Architecture:** A WD33C93 core and a CD-ROM target join the machine in `src/ts` (fitted by a `Machine::create` flag, off by default so the reference hashes stay). The target gets 2048-byte sectors through a lock-free single-slot `SectorPort` served off the audio thread (by `tsemu`/tests between frames, by a reader thread in the app). The floppy `Disk` marks the blocks the OS reads; the app keeps the bytes of what was read per medium, stores them in the Project state, and on restore the engine answers the OS's auto-load prompts with stand-in media built from them.

**Tech Stack:** C++17 (`src/`, `tools/`, `tests/`), JUCE 8.0.16-security (`app/`), CMake; MinGW-w64 i686, MSVC x64, GCC x64 (WSL).

**Spec:** `docs/design/2026-11-15-ts-scsi-design.md` (approved 2026-11-15). The firmware facts it lists (addresses in the OS) are the evidence to cite in decision entries.

## Global Constraints

- Work on branch `plan7-scsi`; merge into `main` with a merge commit only when the user says so. Never push.
- The firmware runs unmodified; MAME is a comparison point, never a reference.
- No JUCE, OS calls or file I/O under `src/`. File I/O in `tools/`, `tests/`, `app/`.
- The audio path is real-time safe after the boot: no allocation, lock or block in `Machine::runFrame` or `Engine::render`; `ens_rt_tests` stays at 0.
- The user's image files are only ever read; never written, never copied into the repo. Disk and CD images come from `ENS_DISK_DIR` (`C:/Users/abart/Desktop/EPS-ASR10 Discs`); tests that need them print "skip: disk images not found" without them.
- Tests never touch the user's settings or memory (`TSR_SETTINGS_DIR` temp folders).
- Never start `TS Reborn.exe` or a plugin GUI; everything runs headless.
- Reference hashes unchanged: boot `3bfc7336098a6def`; renders `3374892bfdc150e6`, `524fcc64af78f175`, `01e3c8622cc8c8be` (the default machine has no SCSI).
- One CD drive, SCSI ID 4. The TS's own ID is 3. Read-only: WRITE(10) answers CHECK CONDITION, DATA PROTECT (sense key 7).
- CD images: `.iso` (size a multiple of 2048) and `.cue` with one `TRACK 01 MODE1/2352`, `INDEX 01 00:00:00`; a missing FILE path falls back to that name in the `.cue`'s folder, matched without case.
- A Project state carries every block the OS read since the instance started or was last restored; no size cap. The Standalone records and stores nothing (A121).
- Decision ids: T25-T29 (machine), A127-A131 (app); `// DECISION <id>:` at the point of use; T12 and A124 updated, not replaced.
- Style: AGENTS.md (C++17, 4 spaces, ~120 columns, `/W4` and `-Wall -Wextra` clean, comments say why and cite).

## Review Focus

1. **The image becomes unreadable mid-load** (file moved, USB drive pulled): the reader replies failure, the target answers CHECK CONDITION, MEDIUM ERROR (3/0x11), the OS shows its error and the machine keeps running. Test in Task 2 (`cd_target_medium_error`) and Task 8 (`cdDriveMissingFile`).
2. **Eject or a new disc while a sector is on its way:** a late reply for the old medium is never served to the new disc. Test in Task 2 (`cd_target_ignores_stale_reply`).
3. **A project saved during a restore** (before the auto-load has finished): the state holds the restored media unchanged, not a half record. Test in Task 9 (`mediaStateDuringRestore`).
4. **A prompt for a disk the project does not hold** (sounds from a source never recorded, or a damaged state): the engine presses *SKIP*, the boot finishes. Test in Task 7 (`engine_restore_skips_unknown_disk`).
5. **A malformed `<Media>` element** (bad base64, a block number past the medium, an unknown kind): that medium is dropped, the rest of the state restores. Test in Task 9 (`mediaStateBadBlobs`).

**Files:**

**Interfaces:**
- Produces (`src/ts/scsi.h`):
  ```cpp
  class ScsiTarget {
  public:
      enum class Phase : uint8_t { DataIn, DataOut, Status };
      virtual ~ScsiTarget() = default;
      // A new command with the host's Transfer Count. DataIn yields exactly `count` bytes (padded with 0 or cut).
      virtual void command(const uint8_t* cdb, int len, uint32_t count) = 0;
      virtual Phase phase() const = 0;
      virtual bool ready() const = 0;          // the next data byte can move (false while a sector is on its way)
      virtual uint8_t readByte() = 0;          // DataIn
      virtual void writeByte(uint8_t v) = 0;   // DataOut
      virtual uint8_t status() const = 0;      // in Status: 0x00 GOOD, 0x02 CHECK CONDITION
  };
  ```
- Produces (`src/ts/sector_port.h`, header-only, atomics, no allocation, no lock): `class SectorPort { public: static constexpr int kBytes = 2048; void ask(uint32_t medium, uint32_t lba); /* audio side, replaces an outstanding ask */ bool answered(uint32_t medium, uint32_t lba, bool& ok) const; const uint8_t* data() const; bool pending(uint32_t& medium, uint32_t& lba) const; /* reader side */ void reply(uint32_t medium, uint32_t lba, const uint8_t* data, bool ok); };` A reply for an ask that has been replaced is ignored.
- Produces (`src/ts/cd_target.h`): `class CdTarget : public ScsiTarget { public: explicit CdTarget(SectorPort& port); void insert(uint32_t medium, uint32_t sectors); /* sectors 0: eject; a change queues one UNIT ATTENTION 6/0x28 */ bool hasDisc() const; uint32_t medium() const; uint32_t sectors() const; /* overrides */ };` Medium ids are chosen by the caller; 0 means none.
- Answers (DECISION T28; cite the design's firmware facts): INQUIRY type 5, removable bit, ANSI version 2, vendor/product of a Toshiba CD-ROM mechanism (service manual p. 62; record the strings chosen), padded to the allocation length; TEST UNIT READY GOOD with a disc, else CHECK CONDITION NOT READY 2/0x3A; UNIT ATTENTION 6/0x28 once after `insert`; REQUEST SENSE: fixed format, 0x70, key at byte 2, ASC at byte 12, ASCQ at 13; MODE SELECT(6): block length from the descriptor, 512 or 2048 accepted, else ILLEGAL REQUEST 5/0x26; MODE SENSE(6): 4-byte header plus one 8-byte descriptor with the current length; READ CAPACITY: last block and length in the current block length; READ(10) in the current block length, each 512-byte block taken from its 2048-byte sector; WRITE(10) DATA PROTECT 7/0x27; other opcodes ILLEGAL REQUEST 5/0x20. Block length after `insert` is 2048. A failed reply: MEDIUM ERROR 3/0x11.

### Task 3: WD33C93 core

**Files:**
- Create: `src/ts/wd33c93.h`, `src/ts/wd33c93.cpp`; `tests/test_ts_wd33c93.cpp`
- Modify: `CMakeLists.txt`, `tests/CMakeLists.txt`

**Interfaces:**
- Consumes: `ScsiTarget` (Task 2).
- Produces: `class Wd33c93 { public: void reset(); /* hardware reset, datasheet 3.2.1 */ uint8_t read(bool a0); void write(bool a0, uint8_t v); void attach(int id, ScsiTarget* t); bool interrupt() const; uint8_t reg(int r) const; uint8_t address() const; /* tests */ };` `a0` false: address register (write) / Auxiliary Status (read); true: the addressed register.
- Behaviour (DECISION T25, T27; datasheet sections cited): registers 0x00-0x1A; every `a0` access steps the address except at 0x18 and 0x19; undefined registers read 0xFF (datasheet 3.0 note 2). Auxiliary Status: bit 7 INT, 6 LCI, 5 BSY, 4 CIP, 0 DBR. Reading SCSI Status (0x17) clears INT. Commands: 0x00 Reset (INT, status 0x00; Own ID's EAF bit 3 set gives 0x01); 0x08/0x09 Select-and-Transfer; others INT 0x40. A command written while INT is set is ignored with LCI. Select-and-Transfer: no target at Destination ID: INT 0x42, Command Phase 0x00. Else the CDB (6, 10 or 12 bytes by group, registers 0x03..) goes to `command(cdb, len, count)` with count from 0x12-0x14; DataIn/DataOut move through the Data register with DBR = `target->ready()` and the count decrementing in 0x12-0x14; then status into 0x0F, Command Phase 0x60, INT 0x16; after 0x17 is read, INT 0x85 (bus free). Everything happens at register accesses; there is no clock (DECISION T27: selection, command and status take no time; the Timeout Period is not modelled).
